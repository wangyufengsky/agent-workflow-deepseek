# R01 execution stop verification

Cancellation retains one request key. Replayed accepted/unknown receipts never dispatch another abort. Abort rejection or pauseTimeoutMs expiry produces UNKNOWN and preserves the in-flight node, rather than claiming it stopped. A late abort acknowledgement or explicit idle outcome reconciles the original receipt; the interrupted attempt becomes cancelled, its node becomes retryable failed/STOPPED, and progress.running is zero. Completed nodes and future pending/ready nodes are preserved. Result submission and late completion cannot revive a stopped execution.

A stop arriving before session creation completes prevents prompt dispatch by throwing from onSessionId, which the managed adapter invokes before SessionRunner.run. The adapter now rejects an unavailable runtime and a false abort acknowledgement instead of reporting success. Normal node timeouts project the execution to UNKNOWN instead of leaving it running indefinitely.

Validation: execution-stop.test.ts (8 offline port-injection tests), execution-control.test.ts (5 HTTP integration tests), startup-recovery.test.ts (5 tests), workspace-cleanup-blockers.test.ts (1 test), npm run typecheck. The final targeted regression run passed all 19 tests. Fault injection verifies local control flow only; no real model or remote stop acceptance was performed. Unknown stop state survives in the operation ledger; across process restart no abort is automatically reissued. GET /api/operations/:key now asks the execution service to inspect the exact original attempt session. Attempt/session identity is saved locally; missing identity falls back to metadata discovery. Only explicit runtime idle reconciles the original cancellation to succeeded/stopped; missing fields, unsupported status endpoints, failed reads and empty discovery remain UNKNOWN. The real OpenCode 1.19 status payload and remote stop acceptance still require native runtime verification.

Follow-up review hardened attempt identity and loop ownership. Explicit retry after a confirmed stop starts a new attempt and invalidates the old scheduling loop; late abort acknowledgements, idle outcomes, text, and result submissions cannot affect the new attempt. Retry is forbidden while any node is still running/unknown. The shared machine declares stopped/failed -> running for explicit retry. Paused active nodes and execution UNKNOWN block workspace cleanup in both preview/confirm behavior and service action projection. Startup recovery preserves stopping attempt identity as UNKNOWN rather than assuming a desktop-process exit stopped its external session.
