# P07 · Workflow graph editor and persisted version differences

The workflow editor now edits the graph that the service compiles. `requires` is authoritative: omitted values preserve the existing ordered legacy catalog; an explicit empty array is an independent root; nonempty arrays are predecessor keys. Editing first materializes legacy dependencies before inserting, deleting or moving array entries. Parallel insertion duplicates the selected step's predecessors and joins its successors. Removing a step reconnects all predecessors to successors. Self/cyclic connections are rejected locally and by the service, including cycles involving legacy implicit edges.

`MethodStepDefinition` retains authored summary, input mapping, output slots, acceptance clauses and canvas coordinates. Catalog save/copy/read/instantiate preserve these fields and explicit roots. Skeleton compilation consumes them and selected roles. The role agent's published role snapshot remains the execution authority when integrated. Actual concurrency remains subject to read-only roles, exclusive workspace writers, configured concurrency and predecessor acceptance.

The React Flow canvas supports node drag, blank-space pan, zoom controls, Ctrl/Command wheel zoom, fit, topological arrangement, edge insertion, edge removal, and ordinary dependency connections. A step selector and numeric coordinates provide keyboard alternatives. The drawer supports parallel insertion, next-step insertion, connecting existing steps and editing predecessor checkboxes. Save UNKNOWN retains the draft and locks mutations, including undo shortcuts; only the original operation is reconciled.

Step templates come from the live service workflow catalog, not example UI data. Insertion copies an independent step definition with a fresh key and rewires dependencies. Search and explicit role selection remain available. Template task range/history is handled separately by P10.

Custom catalog saves/archive now retain immutable previous versions in the same persisted record. `/api/workflows/:id/versions` returns only snapshots actually available; it does not invent versions absent from legacy storage. The comparison modal selects a persisted version and displays actual changed fields and before/after values. The canvas marks added/modified steps with text and icons; removed steps remain visible in the comparison list.

Planning validation retains explicit predecessor reachability even when a candidate inserts intermediate steps. AI cannot silently serialize an explicit parallel root. An extra dependency must explain its basis in the existing edge label and bind an upstream input or overlapping resource; pure ordering preferences are shown through the existing candidate human-decision field and normal candidate review. This adds no execution node or separate approval flow. The planning prompt exposes configured predecessors and authored responsibilities/acceptance, and states that model reasons are claims rather than service facts.
