## 问题清单

### P05-01: 设计“PPT 制作”创作页整体缺失，创建被折叠为作品库弹窗
- **严重度**：P1
- **维度**：S / 结构 / R / T
- **类别**：结构 / 交互
- **设计依据**：`opencode-workflow-design-showcase/originals/main/pages/ppt.html:56`（hero：eyebrow「PPT 制作」、h2「把想法，整理成一份演示。」、lede「先和助手讨论清楚要讲什么，再逐页制作。全程可以改。」）；`:58-72`（创作框：项目 pill → 主题 textarea → 附件/字数/「开始讨论」）；`:73`（未选项目时的 3 个示例想法 chip）；`:74`（三步说明卡：`01 讨论需求`「助手会问清对象、目的和篇幅，必要时读取项目资料」/`02 确认制作方向`「给出大纲和视觉方向，你确认后才开始逐页制作」/`03 逐页制作与检查`「每页生成后自动检查文字溢出与一致性，可随时手动改」）；`:75-76`（底部「最近的演示」+「全部作品」+ 4 张最近作品卡）；`:81`（页头 h1「PPT 制作」+「全部作品」按钮、`states:[empty,ready,files,submitting,error]`）；`originals/main/index.html:97-99`（设计意图：先选项目再写主题、三步做成带示意的卡片、底部“最近的演示”带下一步提示并回到工作台）。
- **实现位置**：`apps/web/src/pages/ppt/PptPage.tsx:239-250`（作品库内容页头「PPT 制作」+「作品/工作台」分段 +「新建演示」）、`:370-382`（创建改为 `PptCreateDialog` 弹窗）；`apps/web/src/pages/ppt/PptCreateDialog.tsx:44-157`（弹窗表单）；`apps/web/src/pages/ppt/` 内无 hero/三步说明卡/示例想法/最近的演示组件（设计文案 grep 无命中）。
- **差异**：设计的主入口是独立创作页（hero 引导 + 大创作框 + 示例想法 + 三步说明卡 + 最近演示）；实现 `/ppt` 默认是作品库，创作收进「新建演示」弹窗，上述五个区块全部不存在，页头的「全部作品」入口也随页面合并消失。合并后默认落点与设计相反（设计默认创作页，实现默认作品库）。承载方式/路由层差异见 GLOBAL `GLB-08`，本报告只记 P05 的区块/文案缺失，不重复计级。
- **原因**：直接原因：创作页未实现，创建入口改为 Modal，作品库成为默认视图（C4/C5）。根本原因：路由层以“单页多视图”承载 `ppt/ppt-works`（决策见 `docs/review/execution-log.md:369`），创作页被当作可由弹窗替代，未建立与设计页面粒度的映射，也未补设计说明（C4）。
- **影响**：首次使用者看不到“讨论→确认方向→逐页制作”的三步预期，也没有示例想法与最近作品引导；设计要求的「最近的演示」快捷入口消失（“下一步提示”能力只在作品卡上部分实现，见 P06-03）；创作页不可深链/刷新。
- **建议**：在 `/ppt` 恢复与设计同构的创作区（hero + 项目→主题→资料创作框 + 三步说明卡 + 最近演示），作品库作为其下方或独立二级视图；若坚持弹窗，需设计确认并补决策说明，同时保留三步说明卡与最近作品入口。
- **验证**：静态；需GUI（首屏结构、断点）
- **关联状态**：`empty, ready, files, submitting, error`（创作页 5 态均无载体）

### P05-02: “先选项目再写主题”的约束与“开始讨论”语义丢失
- **严重度**：P2
- **维度**：A / T / 结构
- **类别**：交互 / 数据契约
- **设计依据**：`ppt.html:54`（`ok = st.proj && st.text.trim().length>=6`：项目是提交前置）；`:60-61`（项目 pill 必选 + hint「演示会使用这个项目的资料和公约」/「演示归属于一个项目，便于引用资料」）；`:64`（未选项目时 textarea `disabled`，placeholder「选择项目后填写」）；`:67`（未选项目时「添加资料」disabled）；`:70`（主按钮「开始讨论」）；`index.html:99`（「先选项目再写主题，与开始任务一致」）。
- **实现位置**：`PptCreateDialog.tsx:26`（projectId 默认空串）、`:81-96`（`<select>` 默认项「不归属项目」）、`:29`（valid 只看主题≥6 字）、`:35`（projectId 为空则不传）、`:132-141`（textarea 未按项目禁用）、`:70`（按钮「保存为演示草稿」）、`:97-103`（项目 hint 改为工程口径）；服务端允许无项目：`packages/engine/src/ppt.ts:104,113`；DTO 可选：`packages/shared/src/api/contracts.ts:964`。
- **差异**：设计要求项目必选后主题框才可用、按钮「开始讨论」直接进入讨论；实现项目可选（默认“不归属项目”）、主题始终可写、按钮语义变为“保存为演示草稿”（创建后由用户在工作台再发起讨论）；项目 hint 与 textarea 占位文案也换成实现自定文案。
- **原因**：直接原因：前端未把项目作为创建前置，按钮按“创建草稿”实现（C5/C6）。根本原因：契约把 `projectId` 设为可选（C1），产品未明确“无项目演示”是否合法，前端选择放宽而非按设计 gate（C6）。
- **影响**：用户可能创建无项目演示，生成时不会读取项目资料，与设计“演示归属于项目”的预期不符；创建动作从“开始讨论”降级为“存草稿”，与设计主流程语义不一致。
- **建议**：恢复“项目必选→主题可写”gate（或在服务/设计层明确记录允许无项目演示的产品决策）；按钮语义回到「开始讨论」（创建后自动发起/聚焦助手讨论），并恢复设计 hint 文案。
- **验证**：静态；需真实服务（无项目创建路径）
- **关联状态**：`empty, ready`

### P05-03: 创建失败/超时/UNKNOWN 的回执被弹窗遮罩吞掉，error 态不可见
- **严重度**：P1
- **维度**：S / A / D / K
- **类别**：状态 / 交互
- **设计依据**：`ppt.html:57`（error state：danger banner「没能开始讨论」+「服务暂时不可用。你写的内容和资料都还在，可以直接重试。」+「重试」按钮；`onclick="DS.setState('ready')"`）；`:81`（states 含 error）。
- **实现位置**：`PptPage.tsx:263-275`（`PptReceiptBanner` 渲染在页面内容层）、`:370-382`（弹窗与页面同级渲染）、`:193-205`（catch 后只 `setReceipt`，不关闭弹窗）、`:252-261`（项目列表读取失败提示也在页面层）；`PptCreateDialog.tsx:16-22`（props 无 error/receipt）、`:44-157`（弹窗内无错误位）；`Modal.tsx:35-45`（scrim + dialog 固定层）；`ds.css:63,291-292`（遮罩 `rgba(0,0,0,.55)` + `blur(2px)`，scrim z-index 40、dialog 51）。
- **差异**：创建失败/超时/unknown 时，服务回执与说明只出现在被遮罩盖住的页面层（视觉被 55% 黑遮罩 + 2px 模糊），弹窗内没有任何失败提示、没有设计要求的「重试」按钮，用户点「保存为演示草稿」后只看到按钮从“正在创建…”恢复，误以为未发生。UNKNOWN 时也没有可见的「核对原操作」入口（该按钮在页面层 banner 上），且对话框每次提交都 `createRequestKey()` 生成新 key（`PptCreateDialog.tsx:33-34`），用户可直接再次提交，存在重复创建风险。弹窗内文案「若没有收到回执，页面会显示 unknown 状态且不会自动重发」（`:150-153`）承诺了实际看不到的反馈。项目列表读取失败时，弹窗也只会显示“服务里还没有项目”（`:97-103`），把读失败误示为无数据。
- **原因**：直接原因：回执展示挂在页面层、弹窗未接入回执状态（C2/C5）。根本原因：写命令回执的展示位置未按“操作发生处”建模，Modal 与页面回执之间没有状态通道（C5）；UNKNOWN 的核对入口只做在页面 banner，模态操作路径不可达（C2）。
- **影响**：P05 的 error 状态实际不可见；创建失败用户会反复重试或误以为创建成功；UNKNOWN 的“不自动重发、按原 key 核对”语义在创建路径上失效。
- **建议**：在创建弹窗内渲染 failed/accepted/unknown 回执（含 requestKey、服务错误、重试/核对按钮），unknown 时禁用再次提交直到核对原操作；恢复设计文案「你写的内容和资料都还在，可以直接重试」；项目读取失败在弹窗内显示读错误而非“没有项目”。
- **验证**：静态；需GUI（遮罩下可见性）+ 需真实服务（制造失败/超时阻塞）
- **关联状态**：`error, submitting`（及协议态 `unknown`）

### P05-04: 创建阶段无法添加资料（`files` 状态无实现）
- **严重度**：P2
- **维度**：S / 结构 / A
- **类别**：状态 / 结构
- **设计依据**：`ppt.html:50`（`st.files` 附件数组：architecture.md 12 KB、design-contract.md 8 KB）；`:66`（附件 chip：文件名 + 大小 + 移除按钮）；`:67`（「添加资料」按钮，未选项目时 disabled）；`:81`（states 含 `files`）。
- **实现位置**：`PptCreateDialog.tsx:75-154`（表单只有项目/版式主题/主题文本，无附件字段）；创建 DTO 无附件：`packages/shared/src/api/contracts.ts:963-969`；附件走创建后的独立接口：`contracts.ts:917-923`、`packages/engine/src/ppt.ts:163`（attach）/`:190`（detach）；前端附件 UI 只在工作台：`PptWorkbenchSteps.tsx:462-630`、`PptWorkbench.tsx:149`（「作品资料」抽屉）。
- **差异**：设计允许在开始讨论前添加/移除资料并在创作框内展示；实现创建弹窗没有附件能力，必须先创建、再进工作台补附件。
- **原因**：直接原因：创建 DTO 不能携带附件，前端把创建与附件拆成两步（C1）。根本原因：契约按“先建后传”设计，与设计“先备资料再开始讨论”的流程不一致；创建成功后也没有立即引导补资料（C4/C5）。
- **影响**：用户无法按设计顺序准备资料；创建后容易忘记补资料，生成时缺少项目/附件依据；`files` 状态无实现。
- **建议**：创建弹窗支持选择/粘贴资料（创建成功后按顺序调用 attach 接口并逐条展示回执）；或创建成功后自动打开「作品资料」抽屉并提示“资料会在生成时使用”。
- **验证**：静态；需真实服务（attach 回执）
- **关联状态**：`files`

### P05-05: 创建弹窗多出设计没有的“版式主题”控件，并暴露内部主题 id
- **严重度**：P3
- **维度**：结构 / T
- **类别**：结构 / 范围

### P06-09: PPT 状态/阶段/命令文案散落在本地常量，未进 `labels.ts`

### P06-10: 项目名缺失时把“项目数据不可用”误示为“未归属项目”
- **严重度**：P3
- **维度**：D
- **类别**：数据语义
- **设计依据**：`ppt-works.html:79`（卡片元信息显示 `项目 · 更新于 时间`，项目是作品归属事实）；METHOD §2 D（无数据/未知必须显示未知与原因，不得混淆）。
- **实现位置**：`PptWorksView.tsx:33-35`（`projectNameFor` 在 `projects` 列表里找不到项目时返回 `undefined`）、`:92,142`（卡片渲染 `projectName ?? '未归属项目'`）、`:166`（筛选下拉 fallback「项目不可用」）；`PptPage.tsx:98-99`（`projectsQuery` 失败时 `projects=[]`）。
- **差异**：作品其实有 `projectId`、但项目列表读取失败或项目已不在列表时，卡片显示“未归属项目”，把“数据不可用/未知”表达成“没有项目”（同一卡片在筛选下拉里却用“项目不可用”，两处不一致）。
- **原因**：直接原因：卡片把 `undefined` 统一映射为“未归属项目”，未区分“无 projectId”与“项目名读取不到”（C6）。根本原因：缺少项目读取失败的分支与原因展示（C2）。
- **影响**：项目列表读取失败时，用户会误认为所有作品都不属于项目；与筛选下拉文案自相矛盾。
- **建议**：区分 `work.projectId === undefined`（未归属项目）与有 id 但项目名不可用（显示“项目不可用/未知”及原因），与筛选下拉 fallback 保持一致。
- **验证**：静态；需真实服务（项目读失败路径）
- **关联状态**：`list`
