### 0.2 最严重的问题（按修复优先级）

1. **P0 `P07-23`（数据诚实）**：PPT 制作方案“保存方案/确认方案”与「加一页」的整份 PATCH 携带 `slides`，服务端 `engine/ppt.ts:233-236` 会把 `productionPages` 全部改写为 `completed/source:manual` 并 `#generation.clear`——逐页制作中途停止/失败后的“部分完成、本次已制作 X/Y、停止原因”被伪造成“全部完成”，导出门槛被放开，可导出缺内容空页。已由 Lead 与交叉核验确认，无有效保护。
2. **P0→P1 `P13-01`（数据诚实/状态误读）**：执行已结束但等待交付时，任务画布情况条渲染绿底 ✓「已完成」（`TaskCanvasPage.tsx:463-466`、`task.css:115`），而设计明确要求「执行已结束 · 等待交付」并拆「执行与验收 / 交付」两事实。交叉核验指出设计禁止的是**任务徽标**绿色完成（实现页头徽标为 wait 色），但情况条绿“已完成”仍会误导用户漏掉交付，故建议降 P1 并与 `P13-02`（情况条缺三段事实）合并修复。
3. **全局页头体系偏离（`GLB-01/02/03/04/05`）**：设计明文规定「页头只放面包屑/页名 + 本页主操作；设计审阅控件（状态、版本、皮肤切换）不进产品页头」「皮肤切换移到设置→外观」。实现却在页头放了 **「展示/审阅」空操作分段**（只写 localStorage，不驱动任何界面/服务状态）、**主题循环按钮**（与设置→外观重复）、**项目数/服务连接 chip**（设计没有、且与侧栏底部运行环境芯片重复）；同时本页主操作下沉到内容区、页头槽位几乎未用，页头与内容标题重复。
4. **UNKNOWN/回执安全链系统性缺失（P1 成组）**：`P08-01`（开始页未知态无锁定/无原请求核对）、`P11-02`（需求画布 UNKNOWN 后可换新 requestKey 重投）、`P14-02`（待处理回答网络不确定被当“未提交”）、`P21-02`（角色保存/发布未明与 409 未闭环）、`P22-04`（设置保存未明时字段仍可编辑、无核对入口）、`DEL-14`（已有原 MR 不核对、可能重复创建）等——违反“未知只按原请求核对、不重发”的既定契约。
5. **契约/服务字段缺失导致设计态不可达（`C1` 出现 162 次）**：知识回答引用上标、需求计划手改、角色 B-02 已发布版本核对、设置 B-10 连接方式/B-11 设计监控间隔、PG/达梦等扩展驱动、任务列表节点级步骤状态与原因、提交图谱与 diff 展开上下文等，均为“服务/DTO 没有字段或端点 → 前端只能降级/不可达”。
6. **交互确认与草稿安全**：`P11-03` 准备独立工作区/开始执行无独立确认；`P05-03` PPT 创建失败/UNKNOWN 回执被弹窗遮罩吞掉；`DEL-07` 实现提供**设计明令禁止**的产品内合并并可置任务完成（与 Git MR 面板“不提供合并按钮”文案矛盾）；`DEL-20` 非 Git 应用“一键写入原目录”无确认对话框。

### 1.2 判定口径

- **设计权威优先级**：`supplement-v5` > `supplement-v4` > `planning/delivery/git/node` 补充稿 > 主稿 `originals/main`；历史备份与旧审查文档只作线索。
- **维度**：S 状态覆盖 / A 操作与回执 / T 文案 / 结构 / R 路由返回 / V 视觉主题 / K 可访问性 / D 数据诚实。
- **状态判定**：`已实现` / `部分` / `缺失` / `无法静态判断（需GUI或真实服务）`；每个区域报告都有逐状态覆盖表。
- **严重度**：P0 阻断主流程/核心数据错误/伪造成功；P1 关键区域或关键状态/操作缺失或明显不符；P2 局部/次要状态与视觉文案；P3 细节。
- **原因编码**（区域报告每条问题均填写“直接原因 → 根本原因”）：
  `C1` 服务/契约缺失（DTO 无字段或无端点） · `C2` 前端状态分支缺失 · `C3` 文案/术语漂移 · `C4` 结构/区域缺失或多余 · `C5` 交互/导航/回执逻辑缺失或不同 · `C6` 数据语义/映射错误 · `C7` 样式/主题/布局偏差 · `C8` 可访问性/键盘/焦点 · `C9` 设计自身矛盾/明确不开放/诚实降级 · `C10` 文档/证据口径与代码不一致。

### 1.3 局限（重要）

- 本次是**静态代码审计**：未运行 GUI，未跑四主题 × 1440/1280/1024 像素级对比，未做完整键盘矩阵；相关结论在区域报告中标注“需GUI”，不作为“已通过/已失败”断言。
- 未调用真实模型、真实 GitLab、PG/达梦/openGauss 等外部服务，未重跑既有 E 系列证据；涉及外部/模型的行为只做代码契约判定。
- 设计参考截图（`design/*.png`）大部分不在仓库可读目录，视觉结论以设计 HTML/inline style/ds.css 与 REVIEW.md 为依据。

### 3.2 UNKNOWN / 回执安全链（跨区域系统性缺口）

设计要求“写操作返回 accepted → succeeded/failed/unknown；UNKNOWN 只能按原请求核对、不重发”，实现中多处缺口：

| ID | 缺口 | 证据 |
|---|---|---|
| `P08-01` | 开始页“请求已发出但没有回执”无锁定、无持久原请求号、无核对入口；传输失败被写成“失败/未创建” | `05-start-workflows-editor.md` |
| `P11-02` | 需求画布 UNKNOWN 后按钮恢复可点，可换新 requestKey 重投 | `06-requirement-planning.md` |

## 5. 跨区域根因总结（问题为什么会出现）

1. **“设计态 → 真实服务契约”的映射缺口（C1 162 次）**：设计稿按完整产品假设写了大量状态（已发布版本核对、引用上标、计划手改、连接方式、监控间隔、图谱、diff 展开、工作区异常家族……），但当前 DTO/端点没有对应字段/接口；前端只能省略、降级或换成简单视图。**这类问题必须“契约先行”**：先补 shared DTO/服务端点，再补前端状态。
2. **异常态被压成“成功/失败”二元（C2+C6 183 次）**：UNKNOWN、部分完成、读取失败保留旧值、交付未完成/已完成、验收审计语义等被压扁，导致误导性展示；根因是状态分支按“主流程”实现，异常/中间态没有独立数据与 UI。
3. **原型评审控件与产品控件边界失守（C4+C5）**：页头主题/展示审阅/项目 chip 等来自设计评审工具或历史实现，未按 v5 说明收敛；页头/内容双层标题与主操作位置说明对 Shell 与页面的职责边界没有落地。
4. **交互回执约定未全站一致执行（C5 94 次）**：仓库已有 requestKey/accepted/unknown/by-key 约定，但开始页、需求画布、角色、设置、MR 创建等入口没有统一的 pending 锁定/原 key 核对组件复用；部分仍用“失败→重试”旧模型。
5. **文案/术语缺单一来源（C3 91 次）**：`labels.ts` 只覆盖领域枚举，页面内仍有大量手写中文（状态、阶段、错误、提示、主题名），导致漂移；应把剩余文案迁入 shared labels 或在页面内集中常量。
6. **样式层是“叠加”而非“对齐”**：`app.css` 与各页 CSS 在复制设计稿后做了局部调整（间距/断点/抽屉宽度），并留下半成品样式（CSS 已写、TSX 未用）；需要一轮“设计样式逐条回归 + 死代码清理”。
7. **文档口径未随实现更新（C10）**：旧审查文档仍把已实现项列为缺口，容易导致重复排期或误判；本报告 §3.8 给出更正清单，建议同步更新 `design-coverage.md` / `remaining-work.md` / `frontend-gaps.md` / `design-parity*.md`。

  1. 四主题（deepseek/warm/spdb/github-white）× 1440/1280/1024 的像素级布局/间距/溢出/对比度；
