# P14 Insights 真实任务计量与筛选（2026-10-20）

基线 b2cb22b；独立范围 Insights 页、计量服务/DTO、TaskService 只读全集和既有 task-usage GET。未改规划记录、PPT、角色、Inbox、设计稿与验收脚本。

只读权威 `originals/main/pages/insights.html:91–105` 要求项目、状态、实际质量、归档筛选；汇总为整个筛选范围；成本分币种；缺失用量与零不同。原实现 taskUsage 只统计 planning，页面 bootstrap 只有 100 个任务、卡片用全局数据、所谓质量实际筛生命周期、规划成本套当前设置币种。

## 实现口径

- 同一次同步 GET 返回完整任务 summary（含 archivedAt）与每任务计量，不使用 bootstrap 的任务截断范围。TaskService allSummaries 复用既有 summary 投影，不改变普通列表分页。
- planning_rounds、attempts、reviews、fixes 沿 executions.task_id 归任务，既包含成功运行也包含失败及重试成本。缺失/无效 total 不当零，明确已知记录和未知记录数；持久记录的真实零仍为零。
- 成本只使用每条规划记录 budget 的原 currency/known；当前设置币种不参与。按 USD/CNY 等分桶，不换算、不跨币相加；无成本字段的执行/评审/修复计为成本未知。成本与 tokens 是否已知独立。只有初始零预算、没有实际 dispatch 的记录不冒充零成本。
- 耗时只累计拥有完整有效起止时间的运行区间，标注“已记录运行时长之和”，不冒充任务墙钟耗时；无起止记录（含当前 fix schema）单独计未知。重试为实际 ordinal>1 的执行尝试次数，明确标注执行重试。
- 项目按 ID（同名显示目录）、生命周期、质量、标题、归档共用一套过滤函数。三个卡片、表格、详情全部来自同一过滤范围。无符合任务和全部未知均明确显示。
- 质量通过要求任务完成、人工验收通过、当前 execution 的最近评审完成且无 open findings；驳回或未处理问题为“存在问题”，其余为待验收/待评审。执行节点成功计数另列，不宣称测试通过数。保留原人工验收服务动作，成功后同时刷新质量和计量快照。
- 刷新同时重读各统计；失败保留上次快照与筛选，明确提示失败和重试，不清成零或插示例数据。
