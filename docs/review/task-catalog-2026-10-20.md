# 任务、需求、模板与首页 · P10 · 2026-10-20

基点 `e85fb08`；只读设计依据：`originals/main/pages/tasks.html` 归档入口、`requirements.html` B-15 只读详情、`templates.html` 模板范围与 B-06 历史自动化档案、`home.html` 的进行中卡；v4 固定模板完整路径与 v5 不新增通知的决定继续保持。实现与证据分开，本文件不替代总需求或全仓验收矩阵。

## 实现

- 任务归档/恢复有标准路由、原请求号和回执。服务只允许已结束且没有进行中/未知规划或运行步骤的任务归档，原因投影到 TaskSummary；归档时间持久保存，普通列表与已归档列表分离，恢复回到已结束列表。归档不会清理工作区、计划、执行或交付。没有增加数据库迁移。
- 需求目录选择行打开只读详情抽屉，显示服务实际状态、计划修订号、更新时间、当前需求原文及输入修订说明。选中不修改任务，“打开画布”保持独立入口；读取中/失败可见。这里没有历史版本选择器，也不把当前需求原文称为对应历史计划的原文。
- 首页的单个“进行中”卡读取真实任务，最多列最近三个活动任务，复用任务状态、规划段内阶段与最近活动；空与服务失败明确展示。下方流程演示保留示例标记。没有增加完成提醒、菜单计数或推送。
- 目录补齐六类固定模板，服务提供报告/代码审查/开发分类。分支、时间、源码与需求文档是实际输入：分支固定到 Git targetSha，工作区确认使用该基线；时间按本机时区的提交时间过滤，保存实际作者/提交者/共同作者正文、统计及逐文件完整差异；源码保存固定 blob/正文，可填写路径，也可通过宿主目录选择或服务目录浏览选择，范围外选择被拒绝。周报/详细设计可填写独立输出目录，实际替换本任务执行提示的文档产出位置，不更改项目设置或授予新权限。代码评审的普通日期选择实际形成日期增量范围，只有“全部历史”走全量；空日期范围保持零分析单元，不回退全量源码。日期通过 Git 服务端过滤后才应用200条上限，超过上限明确拒绝，不拿截断证据冒充完整分析。
- Markdown、DOCX、PDF 按顺序上传，服务校验并保存原文件 SHA-256、字节数与提取正文；DOCX 从实际 document.xml 提取，PDF 使用宿主 pdftotext。没有解析器或无正文时明确失败，不能假装已读取扫描件。源码与文档的固定正文实际进入执行提示。源码 file.read/list 只投影冻结文件，拒绝范围外，和 P06 immutable-blob 通道共存。此源码分析范围不是新增文件系统权限；测试命令仍依赖既有职业命令许可，不声称操作系统沙箱隔离。
- 固定模板创建时保存完整合同；目录发布新版本后，既有任务仍按原合同生成步骤。模板导入、更新、归档保存不可变合同历史，档案也可投影任务内实际冻结合同；旧自动化规则/运行只读保留源读取 `catalog.automation-archive.v1`，空工作区不造旧记录。五页签覆盖概览、历史合同、旧规则/最后检测、运行详情/核对原任务、v1导出；导出排除运行、检测和密钥字段，不会启动或导入自动化。
- 创建预处理先持久受理并阻止同 key 并发派发。任务与创建结果标记在同一事务保存；原 key 查询可以从标记找回已创建任务，或明确结算重启后已中断且没有创建结果的预处理，不自动再创建。网络不明仍由公共 pending-command 日志保留原 key。
