# P09 固定模板运行内容阅读器

权威：只读 `opencode-workflow-design-showcase/originals/main/REVIEW.md` 第19节、`originals/main/pages/run.html` 的文档/源码/单测布局与状态操作。普通任务保留已有阅读器；固定模板依据冻结合同 inputs、模板身份和真实 snapshot 进入专用布局，不按名称猜测。

## 实现与身份

- 文档布局：模板版本、项目、冻结时间、报告版本、逐项需求依据与冻结输入；需求仅取当前执行所绑定计划的 `plan.requirement.<planId>`，不读取后来修改的需求。执行成功且有人工验收才显示已满足，节点成功本身不等于逐项验收。
- 源码/单测布局：范围文件、真实计划分组/快照单元批次、步骤尝试合计、覆盖依据、产物和当前尝试的 verification。覆盖只来自正式 snapshot 单元证据；普通源码模板缺逐文件证明时保留待核对。验证提交计数不宣称为独立验收测试数。
- 报告/产物保留 attempt、resultRevision、hash 身份，并复用已有产物读取/导出能力。选中报告以身份绑定，刷新插入新尝试不会切到另一个报告。
- 输入清单不包含大段正文；同一 run-content GET 通过 inputId/version/sha256 按需读取冻结正文，再核对响应身份。服务不读取当前磁盘替代，旧任务缺快照明确显示缺失；重读失败清空正文，超过128000字符显式显示节选。
- More菜单的归档复用现有服务归档权威：提取同一个只读helper，TaskService写操作和阅读模型都使用它；确认归档后调用原task.archive，保留计划/尝试/产物。
- 本批重试只提交 failedNodeIds，绑定原 requestKey；服务按冻结执行策略投影本批预算与全任务预算禁用原因，不因其他批次的失败步骤预算误禁用本批。accepted/unknown 保留原 key，只允许 GET 核对；停止未确认禁止重试。页面读取失败仍可恢复本地保留的操作 key。
