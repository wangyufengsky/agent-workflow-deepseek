# R02 / R03 职业执行修复证据

- 方法骨架采用步骤选定的 roleId；没有显式职业的旧节点按步骤类型解析职业。
- 确认计划与结束计划调整时持久化已发布职业完整快照，后续发布/归档不改变历史职业修订。
- 实际节点派发使用冻结指令、职责、模型和最短职业/全局时限。指定但不可用的模型失败，不降级到另一个模型。没有职业快照的历史计划明确失败，要求重新确认。
- 实际 OpenCode 会话安装职业工具白名单，原生工具默认拒绝；工作区 MCP 对当前运行节点执行能力、文件路径、精确 argv 上限。命令仍受全局命令列表约束。
- 内置开发/测试默认只能读写当前任务工作区；其他内置职业默认只读。自定义空资源与历史自定义覆盖保持拒绝，命名 workspace 尚无解析器时拒绝。
- 数据库 MCP 增加任务上下文；要求当前运行节点声明数据库连接 id，同时职业有 database_read 能力与资源授权。项目、schema、表范围不在此修复完成口径内。

验证：全仓 typecheck 通过。新增 3 个职业运行单测、1 个真实 Fastify HTTP MCP 权限测试通过；现有 6 个职业目录接口测试、11 个 API/流程目录/计划调整测试通过；现有 13 个 MCP 工具代理测试通过。测试使用临时数据与控制流，不产生模型结果。

未覆盖：真实 opencode-go 派发、OpenCode 1.19.0 的 MCP 工具名归一化与实际拒绝行为、Electron 四主题全状态视觉回归。共享 MCP 进程仍使用内部服务令牌，taskId 不是不可伪造的会话身份；本批没有完成针对恶意模型的跨任务身份隔离。后续需会话绑定的能力令牌，不能把本批上限测试当作该隔离证明。
